# Prospect Insight Engine

Prospect Scan — build prompt for Lovable

What this is

Build a web app called Prospect Scan — an internal sales-research tool for GND Solutions, a Bengaluru-based IoT/cold-chain technology company. A salesperson types in a company name (a potential customer — cold storage operators, logistics firms, pharma distributors), and the tool shows them: what that company actually does, where their operations have gaps GND's technology could fill, and a specific pitch angle to open a sales conversation with.

This is NOT a generic company-database or CRM app. It is a research + gap-analysis tool used before a sales call. The user is a salesperson, moving fast between multiple prospects, deciding what to say on a call in the next few minutes.

Design direction — this is the most important part: do NOT build this as a soft, minimal, centered-hero, pill-button, card-grid SaaS site (i.e. do not make it look like Apple.com or a generic AI-generated landing page). I've already tried that direction and it felt generic and wrong for this tool. Instead, go bolder and more information-dense — think an analyst's workbench or a logistics command console, not a marketing site. Reference points: a Bloomberg terminal's information density (but much better typography and way less clutter), Linear or Raycast's confidence and dark-mode-forward UI, or a customs/shipping manifest's stamped, tabular, no-nonsense character. Real data should feel like real data — tabular, sourced, dense where it needs to be — not softened into rounded pastel cards.

The data

Every researched company has two parts:

1. Facts — researched, sourced claims about the company. Every fact has: the claim itself, a quoted source snippet, and a source URL. Nothing is ever shown without a source — that's the core trust mechanism of this whole tool.

2. Analysis — gaps and a pitch, generated by reasoning over the facts (never from new research — this is a strict two-stage separation, facts first, judgment second, to prevent hallucination). Each gap has: a title, a detail paragraph, a severity (High/Medium/Low — this is a categorical judgment call, NOT a numeric score, don't invent a fake percentage for it), which GND service line it maps to, and a "based_on" citation pointing back to the specific fact it came from. There's also one pitch: an "angle" (a paragraph framing the opportunity) and an "opener" (one literal sentence a salesperson could say or send).

GND's five service lines gaps get mapped to: Cold Chain Management (ThinxFresh), Warehouse Management, Asset Tracking & Monitoring, Product Engineering, Platform.

There are 24 companies like this already researched, ranging from tiny family-run operators (like the one above) to large NSE-listed logistics companies, spanning India, US, UK, Germany, France, Spain, Singapore, Dubai, Australia. Vary the mock data across that range so the design has to handle both a 3-fact tiny company and a 10-fact enterprise one gracefully.

Screens and flows needed

1. Browse / search screen — the entry point. Needs:

A way to see all researched companies at a glance, with enough info to triage (name, industry, HQ, a quick severity summary — e.g. how many high/medium/low gaps) without opening each one.

A search box with live autocomplete-style suggestions as you type, that distinguishes between "already researched" (instant) and "not yet researched, would need a new search" (clearly different, e.g. a different visual treatment or label).

A small, honest "search engine" indicator/selector near the search — right now only one engine actually works (label it "Groq"), others should appear listed but disabled/"coming soon", not fake interactive.

2. Live search flow — when you search a company that isn't researched yet:

Trigger a "searching" state with a genuine loading/progress animation (like Claude or ChatGPT's thinking indicator) — and show real staged progress text as it goes: "Searching the web for facts…" → "Reasoning about gaps…" → "Fact-checking citations…"

If the researched industry doesn't look like cold-chain/logistics/pharma (GND's actual focus), pause and show a clear warning asking the user to confirm before continuing — don't silently force a pitch onto an unrelated company.

Once done, land on a preview/review state — not auto-published. Show the full researched result with two clear actions: Save (publish it, add to the real list) or Discard (throw it away, nothing kept). This review gate matters — nothing should reach the main list without a human approving it.

3. Individual company report screen — this is the one that most needs to feel considered, not templated. Requirements driven by real feedback from using an earlier version:

Must not require much scrolling to see the gaps — that was the single biggest complaint about the previous design. Gaps are the most important content; a user should reach them with near-zero scrolling, not after scrolling past a big hero and a full list of facts first.

Show: company name + key stats (industry/HQ/founded/size), the list of gaps (each with severity, a short title, and expandable detail), the sourced facts (each fact's claim should be a clickable link straight to its source — don't just show a raw URL as separate text, make the actual claim/statement the hyperlink), and the pitch (angle + a literal opener line, with a copy-to-clipboard action).

Each gap should visually communicate severity as more than a text label — some kind of real visual weight/meter, not just a colored word, but don't fabricate a fake precise number (the underlying data only has High/Medium/Low, nothing more granular — represent that honestly, e.g. as a 3-tier visual meter, not "73%").

A way to export/print/download the report as a standalone file to share.

Explicit constraints

This is an internal B2B tool for salespeople, not a consumer product or marketing site. It should feel like a serious working tool, not a polished demo.

Every fact must visibly trace to a real source. Never design a state that hides or de-emphasizes sourcing — that traceability is the whole point of the tool.

Don't invent numeric scores/percentages anywhere the underlying data doesn't actually have one (severity is categorical: High/Medium/Low, nothing more precise than that exists).

Build it first with realistic mock/seed data covering the range of company sizes described above — a live backend can be wired up later.

What to actually deliver

A working prototype covering all three screens above, using realistic seeded data (multiple companies spanning small/obscure to large/enterprise), with the live-search flow simulated (fake delay + staged progress text is fine for now). Prioritize getting the report screen's information hierarchy right — that's the screen a salesperson actually spends time on.
